# Design Context — Rei Ops Room

## Target audience
Developers (primarily the project owner) monitoring and steering Rei, an autonomous
AI agent that picks up GitHub issues and executes them. Used as an always-on
dashboard on a second monitor, plus quick check-ins from a phone.

## Use cases
- Glance: "is Rei working, on what, and is it going well?"
- Steer: submit direct tasks, approve issues, toggle autopilot, generate handoffs.
- Audit: success metrics, costs, memory, run logs, event history.

## Brand personality / tone
"Rei's Night Studio" — a cozy late-night pixel-art studio, warm and characterful.
Rei is a character (pixel sprite in a canvas room), not a faceless service.
The UI should feel like a well-worn desk lamp workspace: warm, calm, a bit playful,
never corporate, never "AI dashboard" (no navy + neon cyan glow, no glassmorphism).

## Visual system
- Palette: warm near-black espresso backgrounds, cream ink, honey amber primary,
  sage = success, terracotta = error, dusty lavender = rest/memory,
  moonlight blue = info/labels. Defined in `public/styles.css` `:root`.
- Type: Silkscreen (pixel display — brand + panel labels only),
  Bricolage Grotesque (headings/body), Spline Sans Mono (data).
- Surfaces: solid panels, crisp 1px warm borders, hard offset shadows
  (retro-game chunk), small radii. No blur, no glow-for-decoration.
- Motion: staggered panel reveal on load, ease-out-quart, state-change feedback
  only. Respect prefers-reduced-motion.
- Canvas room: "dollhouse cutaway" of a warm wooden house — ceiling beams with
  string lights, plaster back wall, front door (agents spawn by walking in
  through it, never materialise), wood plank floor with perspective, per-zone
  room mats with corner posts and hanging signs. Architecture constants live in
  `ARCH` in `public/app.js`; furniture and actors render in one depth-sorted
  pass so agents never float above desks. Clickable: agents (info bubble),
  floor lamp (toggle), coffee mug (steam), plant (confetti).

## Constraints
- Vanilla JS + CSS only, no frameworks, no build step, ESM modules in `public/`.
- All element IDs are load-bearing — `app.js` and panel modules bind by ID.
- Legacy CSS variable names (`--cyan`, `--mint`, `--amber`, `--rose`, `--violet`,
  `--muted`, `--ink`, `--panel*`) are referenced from JS-generated inline styles;
  keep the names, retune the values.
